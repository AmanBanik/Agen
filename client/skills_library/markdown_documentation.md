# Skill: Markdown Documentation Best Practices

## Core Principles
1. **Structured Hierarchy**: Always use a single `# H1` for the title. Use `# H2` for main sections and `# H3` for subsections. Never skip header levels.
2. **Scannability**: Avoid long walls of text. Use concise bullet points, bold emphasis for key terms, and numbered lists for sequential workflows.
3. **Table Usage**: Compare multi-dimensional information (e.g., model metrics, hyperparameters, tool alternatives) using GitHub-flavored Markdown tables.

## Visual & Formatting Elements
* **Code Blocks**: Always specify the syntax language in fenced code blocks (e.g., ````python`, ````bash`, ````sql`, ````json`).
* **Alerts & Callouts**: Highlight critical warnings and tips using GitHub-style blockquote alerts:
  > [!IMPORTANT]
  > Essential requirements or breaking design decisions.
  > [!TIP]
  > Performance optimizations and shortcuts.
  > [!WARNING]
  > Potential pitfalls, memory leaks, or data loss hazards.
* **Mermaid Diagrams**: Visualize architectures, data pipelines, and decision trees using fenced blocks with language `mermaid`.
